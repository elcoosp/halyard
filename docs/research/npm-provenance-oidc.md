# Research: npm provenance & trusted publishing (VERIFY, M0.6)

**Checked:** 2026-11-12 · **Source:** npm docs, "Generating provenance
statements" <https://docs.npmjs.com/generating-provenance-statements>
(fetched live)

## Verified facts

- npm provenance = two attestations: **Provenance attestation** ("publicly
  providing a link to a package's source code and build instructions from
  the build environment") and **Publish attestation** ("generated by the
  registry when a package is published by an authorized user"), both signed
  by Sigstore and logged in a public transparency ledger.
- Requirements: npm **public registry**, npm CLI ≥ **9.5.0**, a **cloud
  CI/CD provider on a cloud-hosted runner** — "Today this includes GitHub
  Actions and GitLab CI/CD" (self-hosted runners excluded) — and a
  `package.json` repository matching the publishing CI host **case-sensitively**.
- GitHub Actions musts: `permissions: id-token: write`, hosted runner,
  publish via `npm publish --provenance`; first publish needs
  `--access public`.
- **Trusted publishing (OIDC):** "provenance attestations are automatically
  generated for your packages without requiring the --provenance flag" and
  it "eliminates the need for access tokens in your CI/CD workflows".
- Equivalent switches for third-party publishers: env
  `NPM_CONFIG_PROVENANCE=true`, `publishConfig: { "provenance": true }`, or
  `.npmrc` `provenance=true`.
- Limitation (docs' own words): provenance "does not guarantee the package
  has no malicious code".

## Design consequences (feeds M13.6 / §13)

- HALYARD's `publish.npm.provenance = true` maps directly onto
  `--provenance` / `NPM_CONFIG_PROVENANCE`.
- HALYARD must refuse provenance publishing outside supported cloud CI
  (fail with E-PUB-* explaining `id-token: write` + hosted runner), and must
  pass `--access` on first publish (`publish.npm.access`).
- Tokenless path = npm trusted publishing (OIDC); HALYARD should prefer it
  when the workflow provides an OIDC token, falling back to `NODE_AUTH_TOKEN`.
