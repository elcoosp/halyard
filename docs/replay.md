## Policy decisions

- **Tag template:** discovery's default `{name}-v{version}` template cannot map these repos' repo-wide `v{version}` tags; the replay overrides every package's template with `v{version}` (equivalent to a `tag_template = "v{version}"` declaration in the repo's `halyard.toml`). The replay therefore validates the bump algebra and the planning pipeline, not template discovery.
- **Gate scope:** the §17 M2.7 ≥ 95 % agreement gate applies only to repos marked `conventional = true` in `corpus/replay.toml`; free-form-subject repos (serde, ripgrep) are reported for triage only.
- **Initial releases:** tags whose parent commit is a root commit are noted as `initial-release` and excluded from the agreement totals.
- **Read-only corpus:** replay runs against a `git clone --shared --no-checkout` copy under the system temp dir; the pinned clones under `corpus/clones/` are never modified.
- **Triage categories:** `non-conventional` (window subjects are not conventional), `explicit-bump` (plan emitted no release), `revert` (a revert is in the window), `expected-divergence` (maintainer-chosen version differs from pure conventional algebra), `initial-release`, `plan-declined`.
- **Plan-declined tags:** a release the planner declines wholesale (fail-closed on unrewritable requirement text, e.g. a member pinned with a quoted exact requirement) is recorded as `plan-declined` and excluded from the agreement totals, the same class as initial releases: the agreement metric measures releases halyard can contractually plan (§11), not ones the engine must refuse.
